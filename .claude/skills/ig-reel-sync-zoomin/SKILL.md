# IG 릴스 싱크 줌인 (ig-reel-sync-zoomin)

지나쌤이 `news-bento-card`로 만든 카드(4칸)와 음성 mp3를 주면, 음성의 1~4번 문장에 맞춰 해당 칸이 화면 중앙으로 확대됐다가 돌아오는 영상을 만든다. 음성은 지나쌤이 직접 만든 것만 쓴다(Claude는 음성을 생성하지 않는다). 설명·항목명은 한글.

## 0. 입력 확인 (만들기 전)
- 카드: HTML(`card*_v*.html`)과 PNG. 칸 좌표는 news-bento-card 기준 A(48,470,580×533) B(652,470,380×533) C(48,1027,380×533) D(452,1027,580×533), 모서리 반지름 44.
- 음성 mp3: 카드 수만큼. **카드 번호 ↔ 음성 파일 순서를 대조**한다. 지나쌤이 "카드 7,8,9 순서대로 첨부"라고 하면 메시지에 @멘션된 순서가 카드 순서다(업로드 시각·파일명 순서와 다를 수 있으니 멘션 순서를 우선). 뒤집힌 것 같으면 만들기 전에 확인.
- 음성 한 개 = 예문 4문장(카드의 01~04 칸 순서). 칸 순서는 A→B→C→D.
- 말하는 새 캐릭터는 기본 포함(초록 새, /home/claude/out/reel/talkkit.py의 `talk_sprite`, `mouth_envelope`). 지나쌤이 빼 달라고 하면 뺀다.

## 1. 싱크 (추정 금지 원칙)
1. `ffmpeg -i mp3 -af silencedetect=noise=-33dB:d=0.12 -f null -`로 쉼을 구한다. 쉼 사이를 발화 구간(segs)으로 본다(0.08초 미만 구간은 버린다).
2. **쉼이 정확히 4개(내부 3 + 끝 1)로 문장 사이에만 있으면 그 시각을 그대로 문장 경계로 쓴다.** 이것은 추정이 아니다.
3. 한 문장 안에서도 쉬는 음성(천천히 읽는 경우)이면 쉼이 많아 경계를 확정할 수 없다. 이때는 구간 3개 분할을 조합 탐색한다: 각 문장의 (그룹 발화 시간 ÷ 전체 발화 시간) 과 (문장 단어 수 ÷ 전체 단어 수)의 차이 제곱합을 최소화하고, 긴 쉼에 약간의 보너스(0.004×쉼 길이)를 준다. **이 경우는 추정이므로 결과 설명에 반드시 알리고**, 어긋난 박스는 영상 번호·박스 번호를 받아 그 박스 시각만 고친다.
4. 음성 맨 앞에 짧은 숨소리(0.3~0.4초 구간 뒤 긴 쉼)가 있으면 첫 박스가 음성보다 일찍 커질 수 있다. 이 점을 한 줄로 알린다.
5. 총 길이 = 음성 길이 + 0.5초(`-af apad -shortest`).

## 2. 동작 (30fps, 1080×1920)
- 박스 i는 문장 i 시작 −0.05초에 확대 시작(첫 박스는 0초), 이징 easeInOutCubic 0.40초.
- **문장을 읽는 동안 확대 유지**, 문장 끝 +0.03초에 복귀 시작, 0.35초(다음 확대 시작 전에 끝나도록 필요하면 단축). 지나쌤이 "1초만 유지"를 원하면 유지 시간을 1초로 줄인다(기본은 문장 길이만큼).
- 확대 배율: A·D(580폭) 1.65배, B·C(380폭) 2.25배. 목표 중심 (540, 900). 확대 박스가 상단 알약(y 220~286)·하단 핸들(y 1588)을 가리지 않는 크기여야 한다.
- 확대 중 배경 카드는 검정 62%로 어둡게(Image.blend), 확대 박스 뒤에 그림자(블러 30, 알파 150×진행도).
- 박스 위치·크기는 원래 칸 중심 → 목표 중심, 배율 1 → 목표 배율을 같은 이징으로 보간한다.
- 말하는 새: 하단 중앙(중심 x 540, 아래 y 1890, 높이 200). 핸들(y 1588) 아래에 둔다.

## 3. 렌더링
1. 카드 HTML을 고해상도로 캡처한다: `google-chrome --headless --no-sandbox --disable-gpu --hide-scrollbars --force-device-scale-factor=2.5 --window-size=1080,1920 --screenshot=카드_hi.png file://.../카드.html` → 2700×4800. 확대해도 선명하다.
2. 배경 = hi를 1080×1920으로 LANCZOS 축소. 칸 이미지 = hi에서 칸 좌표×2.5로 잘라 둥근 모서리 마스크(반지름 44×2.5)를 알파로 씌운다.
3. 프레임 루프: 배경(또는 어둡게 블렌드) → 그림자 → 확대 칸(BICUBIC 리사이즈) → 새. PIL → ffmpeg rawvideo 파이프, `-c:v libx264 -preset medium -crf 18 -pix_fmt yuv420p -c:a aac -b:a 192k -af apad -shortest`, 음성은 `-i mp3 -map 0:v -map 1:a`.
4. 시간 이징·구간 계산은 모두 초 단위로 계산해 `t = i / 30`으로 평가한다(활성 칸이 겹치지 않게 복귀 시간 `to = min(0.35, max(0.15, next_zi − zo))`).

## 4. 확인 (렌더 후)
- 카드당 4개 확대 구간 + 기본 상태에서 프레임을 뽑아 한 장 시트로 Read: 확대 칸이 잘리지 않는지, 알약·핸들·새와 겹치지 않는지, 박스 안 글자가 선명한지.
- ffprobe로 해상도 1080×1920, 오디오 aac, 길이(음성+0.5초) 확인.
- SendUserFile(attach)로 카드별 mp4를 보낸다. 답변은 짧게: 음성 배정(카드↔화자), 싱크 방식(쉼 4개로 확정 / 단어 수 추정 여부), 유지 시간 방식, 새 위치. 재생해 보고 어긋난 박스를 영상 번호+박스 번호로 알려 달라고 한 줄.

## 5. 하지 말 것
- 음성 생성 금지(스크립트만). 웹 사진·실존 인물 사진 사용 금지.
- 알약·핸들·캐릭터 외 장식(자막, 효과음, 로고 등)을 임의로 추가하지 않는다.
- 쉼 개수로 싱크를 맞춘 척하지 않는다: 추정이면 추정이라고 알린다.
